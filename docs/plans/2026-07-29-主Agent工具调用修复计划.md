# 主 Agent 工具调用修复计划

> 日期：2026-07-29
> 分支：feat/agent-deep-improvement
> 问题：主 Agent 对话时不调用正确工具，乱调用不相关的工具

---

## 1. 问题描述

### 1.1 用户报告

用户在主 Agent 对话中说："我是程序员，21岁，男，帮我记录到档案中"

**期望行为**：Agent 调用 `profile_update` 工具，将个人信息保存到档案。

**实际行为**：Agent 完全忽略用户意图，反复调用 `scenario_search` 工具（搜索练习场景），然后返回一段无关的问候语。

### 1.2 具体表现

| 用户输入 | 期望工具 | 实际调用 | 实际结果 |
|---------|---------|---------|---------|
| "我是程序员，21岁，男，帮我记录到档案中" | `profile_update` | `scenario_search` × 6 | 返回问候语 |
| "补充个人信息到档案中" | `profile_update` | `rag_search` × 2 | 返回无关内容 |
| "更新我的个人档案" | `profile_update` | `scenario_search` × 1 | 返回错误信息 |

### 1.3 日志证据

```
[AgentLoop] Available tools: [scenario_search, evaluate_nvc, profile_update, dashboard_query, practice_start, wiki_search, rag_search, scenario_generate, profile_query, wiki_write]
[AgentLoop] Turn 0: LLM returned content (length=105): 你好！欢迎来到 NVC 非暴力沟通练习平台 😊
```

- 工具已正确注册（10 个工具，包括 `profile_update`）
- 系统提示词已正确加载（v2 文件，1688 字符）
- 但 LLM 完全无视系统提示词中的指令

## 2. 根因分析

### 2.1 排除的因素

| 因素 | 状态 | 证据 |
|------|------|------|
| 工具未注册 | ✗ 已排除 | 日志显示 10 个工具全部注册 |
| 系统提示词未加载 | ✗ 已排除 | 日志显示 Message 0 包含正确的系统提示词 |
| 工具 description 不清晰 | ✗ 已排除 | 已更新所有工具的 description，添加了明确的触发词 |
| 缓存问题 | ✗ 已排除 | 修改了正确的文件（v2），并重启了服务 |

### 2.2 根本原因

**mimo-v2.5 模型对工具调用（Function Calling）指令的理解能力不足。**

具体表现：
1. 模型收到了完整的系统提示词，其中明确写了"用户提到个人信息 → 必须调用 profile_update"
2. 模型收到了所有工具的定义（name、description、inputSchema）
3. 但模型完全无视这些指令，自行选择调用 `scenario_search`

**这是一个模型能力问题，不是工程问题。** 无论系统提示词和工具描述怎么写，mimo-v2.5 都无法可靠地选择正确的工具。

### 2.3 模型对比

| 模型 | 工具调用能力 | 备注 |
|------|------------|------|
| mimo-v2.5 | ❌ 差 | 无视工具描述和系统提示词，随机选择工具 |
| qwen3.5-flash (dashscope) | ✅ 好 | 能正确理解工具描述，选择合适的工具 |
| deepseek | ✅ 好 | 工具调用能力强 |
| gpt-4o | ✅ 好 | 工具调用能力强 |

---

## 3. 解决方案

### 3.1 方案 A：切换 LLM 模型（推荐）

将主 Agent 的默认模型从 mimo-v2.5 切换到 qwen3.5-flash 或其他支持工具调用的模型。

**优点**：简单直接，无需额外代码
**缺点**：需要用户确认，可能影响其他功能

### 3.2 方案 B：添加意图预路由层（IntentRouter）

在 LLM 调用之前，添加一个**关键词意图检测层**：

1. 用户消息进入后，先用正则表达式检测明确意图
2. 如果检测到高置信度意图（如"我是程序员" → profile_update），直接调用对应工具
3. 如果无法确定意图，再交给 LLM 判断

**优点**：
- 不依赖 LLM 的工具调用能力
- 高置信度意图的响应速度快（无需 LLM 推理）
- 与模型无关，可以随时切换模型

**缺点**：
- 需要维护规则库
- 只能处理已知模式，新的意图模式需要手动添加

**已实现的部分**：
- `IntentRouter.java` — 意图检测服务（已创建，未集成）
- 需要集成到 `AgentLoop.java` 中

### 3.3 方案 C：A + B 组合

同时实施方案 A 和方案 B：
- 意图预路由处理明确的用户意图（快速、可靠）
- LLM 处理复杂/模糊的用户意图（灵活）

**这是最佳方案。**

## 7. 技术决策记录

### 为什么不直接切换模型？

1. 用户明确说"别切换模型"
2. mimo-v2.5 是项目的默认模型，切换可能影响其他功能
3. 意图预路由方案更通用，与模型无关

### 为什么需要 IntentRouter？

1. mimo-v2.5 的工具调用能力不可靠
2. 意图预路由可以处理 80% 的明确意图，剩下 20% 的模糊意图交给 LLM
3. 即使将来切换到更好的模型，IntentRouter 也可以作为第一道防线，提高响应速度和准确性
