# 主 Agent 对话混乱问题深度分析

> 日期：2026-08-03
> 现象：用户问"我总结过哪些关于心理学的笔记"，Agent 回答完全离题（"职场冲突""说话太直接"等无关内容）

---

## 一、问题现象复现

### 用户实际对话序列

| 轮次 | 用户消息 | Agent 回复 | 问题 |
|------|----------|------------|------|
| 1 | "我总结过哪些关于心理学的笔记" | "看起来你之前可能尝试搜索过一些内容但没有找到结果。没关系，我可以帮你重新搜索。请问你想找什么内容呢？" | wiki_search 搜到了空结果，但回复没有告知用户"没找到"，而是假装能帮忙重新搜索 |
| 2 | "我的个人笔记" | "我注意到你提到了'职场冲突'，这是一个常见的沟通挑战..." | **严重离题**：用户没提过职场冲突，Agent 凭空捏造 |
| 3 | "我说的是你去检索我的个人知识库看看里面有没有心理总结的笔记" | "我理解你的感受。当别人说话太直接时，确实容易让人感到不舒服。" | **完全答非所问**：用户明确要求搜索知识库，Agent 却在讨论"说话太直接" |

## 三、根因分析

### 根因 1：工具调用结果未保存到对话历史（最核心）

**位置**：`NvcAssistantService.java:69-74`

```java
Flux<AgentEvent> processedStream = eventStream
    .doOnNext(event -> {
        // 只保存 CONTENT 事件！
        if (event.type() == AgentEvent.AgentEventType.CONTENT) {
            saveAssistantReply(convId, userId, event.data(), assistantSeq);
        }
    })
```

**问题**：只有最终的 `CONTENT` 事件被保存到数据库。`TOOLCALL_START`、`TOOLCALL_END` 事件（包含工具名、参数、结果）全部丢失。

**后果**：
- 下一轮对话时，`ContextManager` 从数据库加载历史消息，只看到用户消息和助手最终回复
- **LLM 完全不知道自己之前调用了哪些工具、得到了什么结果**
- 这就是为什么第 2 轮 Agent 又重复调用了 `wiki_search`（同样的查询"心理学"），因为它不知道第 1 轮已经调用过并返回了"没有找到"

**流程图**：

```
第 1 轮：
  用户: "我总结过哪些关于心理学的笔记"
  AgentLoop: wiki_search("心理学") → "没有找到" → LLM 生成回复
  保存到DB: [用户消息] + [助手回复]    ← 工具调用记录丢失！

第 2 轮：
  用户: "我的个人笔记"
  ContextManager 从DB加载: [用户消息1] + [助手回复1] + [用户消息2]
  LLM 看到的上下文完全不知道第 1 轮调用过 wiki_search
  → LLM 重新调用 wiki_search（重复！）→ 又是"没有找到"
  → LLM 开始幻觉：调用 rag_search、scenario_generate...
```

### 根因 2：System Prompt 工具描述过于狭窄

**位置**：`nvc-assistant-system-v2.st`

```
## wiki_search — 搜索个人笔记
**触发词**：我的笔记、之前的记录

## rag_search — 搜索 NVC 知识
**触发词**：什么是NVC、NVC理论、四要素
```

**问题**：
- `wiki_search` 的触发词只列了"我的笔记""之前的记录"，用户说"心理学笔记""心理总结"时 LLM 不确定该用哪个工具
- `rag_search` 的触发词是 NVC 相关的，但用户问的是心理学，LLM 在不确定时可能错误地选择 `rag_search`

### 根因 3：LLM 在工具失败后不遵循 System Prompt 指令

System Prompt 明确说：
```
4. **工具调用失败时，告诉用户出了什么问题，不要换一个不相关的工具**
```

但 LLM 完全没有遵守：
- `wiki_search` 返回"没有找到" → LLM 不告诉用户，而是调用 `rag_search`
- `profile_update` 返回"缺少用户ID" → LLM 完全忽略，继续调用 `rag_search`
- 最终回复内容与用户问题毫无关系

**原因**：这可能是因为工具调用结果没有保存到上下文（根因 1），LLM 在第 2/3 轮时看到的上下文不完整，导致它无法正确理解当前对话状态。

### 根因 4：AgentLoop 多轮工具调用时上下文污染

**位置**：`AgentLoop.java:115-188`

```java
while (turn < MAX_TOOL_CALL_TURNS) {
    ChatResponse response = callLlm(messages);
    // ...
    // 工具结果加入 messages 列表
    messages.add(assistantMessage);
    messages.add(ToolResponseMessage.builder().responses(toolResponses).build());
    turn++;
}
```

**问题**：在同一个 turn 内，LLM 可以连续调用多个工具。但当 `wiki_search` 返回"没有找到"后，LLM 没有停止并告知用户，而是继续调用 `rag_search` 和 `scenario_generate`。这说明 LLM 在同一轮内对工具结果的处理逻辑有问题。

## 五、解决方案

### 方案 1：保存工具调用记录到对话历史（核心修复）

**目标**：让 LLM 在后续轮次中能看到自己之前调用了哪些工具、得到了什么结果。

**实现**：在 `NvcAssistantService` 中，将工具调用事件也保存到消息表。

```java
// 在 doOnNext 中，除了保存 CONTENT，还要保存工具调用记录
.doOnNext(event -> {
    switch (event.type()) {
        case CONTENT -> saveAssistantReply(convId, userId, event.data(), assistantSeq);
        case TOOLCALL_START -> saveToolCallStart(convId, userId, event, assistantSeq);
        case TOOLCALL_END -> saveToolCallEnd(convId, userId, event, assistantSeq);
    }
})
```

**消息表设计**：复用现有的 `NvcAssistantMessageEntity`，增加 `toolCallsJson` 字段存储工具调用记录。

### 方案 2：优化 System Prompt 的工具描述

**目标**：让 LLM 更准确地选择工具，减少误调用。

**改进**：
```
## wiki_search — 搜索个人笔记
**触发词**：我的笔记、之前的记录、搜索笔记、我总结过、我记录过、心理学笔记、个人知识库
**关键判断**：当用户提到"我的""个人的""之前记录的""总结过的"，都应使用此工具

## rag_search — 搜索 NVC 知识
**触发词**：什么是NVC、NVC理论、四要素、非暴力沟通概念
**关键判断**：仅当用户明确询问 NVC 理论知识时使用，不要用于搜索个人笔记
```

### 方案 3：在 System Prompt 中强化工具失败处理规则

**目标**：让 LLM 在工具失败时如实告知用户，而不是继续调用无关工具。

**改进**：
```
# 核心原则（必须遵守）

5. **工具返回"没有找到"时，必须如实告知用户"没有找到相关内容"，然后询问用户是否要尝试其他搜索词**
6. **一次对话中不要连续调用超过 2 个工具，除非用户明确要求**
7. **绝对不要编造用户没有提到的内容（如"职场冲突""说话太直接"等）**
```

### 方案 4：AgentLoop 中增加工具调用结果的上下文注入

**目标**：在同轮多工具调用时，让 LLM 能正确处理工具失败的结果。

**实现**：在工具结果消息中增加更明确的指令：

```java
// 工具返回空结果时，在 ToolResponse 中注入提示
if (result.result().contains("没有找到")) {
    responseText = "搜索结果为空。请告知用户未找到相关内容，并询问是否要尝试其他搜索词。不要调用其他工具。";
}
```

| 优先级 | 方案 | 影响范围 | 实现难度 |
|--------|------|----------|----------|
| P0 | 方案 1：保存工具调用记录 | 核心修复，解决上下文丢失问题 | 中（需要改消息保存逻辑 + ContextManager） |

## 七、总结

**核心问题是"记忆断裂"**：Agent 调用了工具、得到了结果，但这些信息没有保存到对话历史。下一轮对话时，LLM 完全不知道之前发生了什么，导致：

1. 重复调用已失败的工具
2. 编造不存在的对话内容（幻觉）
3. 回复与用户问题完全无关

修复的核心是**让工具调用记录成为对话历史的一部分**，这样 LLM 在后续轮次中能看到完整的对话上下文，包括工具调用和结果。
